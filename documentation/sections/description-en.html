Employment Data Cube: Description back to table of contents

The W3C Data Cube vocabulary is used to generate the employment data cube. This vocabulary is a W3C recommendation for publishing multidimensional data on the Web, facilitating its structured representation, interoperability, and reuse. Furthermore, this vocabulary is compatible with the SDMX (Statistical Data and Metadata eXchange) standard, which is widely used for the exchange of statistical data and metadata between organizations.
As shown in Figure 1, the W3C Data Cube contains various concepts and properties that allow for the description of statistical data at different levels of aggregation. In this vocabulary, the model is organized around the qb:DataSet concept, which represents a dataset defined according to a structure specified by a qb:DataStructureDefinition and realized through a set of observations represented as qb:Observation. Specifically, this vocabulary defines, for example, a data cube dataset—represented by the instance ex:dataset/DS_EmploymentIndicators—to which a set of observations can be linked, as well as a single data structure, represented by the instance edintemp:DSD_EmploymentIndicators. The components of this structure are as follows:
  • qb:DimensionProperty: a component that identifies the dimensions of the observations, such as the administrative region, the reference period, sex, age, economic activity, sector, or type of contract. Dimensions typically draw their values ​​from code lists or classifications, usually represented using SKOS.
  • qb:MeasureProperty: a component that represents the measured value of the observed data. In this cube, the measures correspond to employment indicators, such as the number of active persons, employed persons, unemployed persons, job seekers, registered contracts, registered unemployment, Social Security affiliations, unemployment rate, employment rate, jobs, employment profiles, and the total number of individuals.
To define these dimensions and measures, several reference vocabularies are reused:
  1. SDMX (Statistical Data and Metadata eXchange) vocabularies:
    • sdmx-dimension: reused as a foundation for general statistical dimensions, particularly through specialization relationships such as edintdimension:refAdminRegion, edintdimension:refPeriod, edintdimension:sex, and edintdimension:age.
    • sdmx-measure: reused as a foundation for various cube measures, defined as subproperties of sdmx-measure:obsValue.
  2. Territorial and temporal vocabularies:
    • esadm: reused to indicate that the edintdimension:refAdminRegion dimension can take values ​​corresponding to municipalities, neighborhoods, or districts.
    • OWL-Time: reused to model the temporal dimension, establishing that edintdimension:refPeriod has time:Interval as its range.
  3. SKOS code lists:
    • The edintdimension:sector dimension reuses the public sector scheme published at datos.gob.es as its code list.
    • The edintdimension:economicActivity dimension reuses a controlled classification of economic activity, such as CNAE 2025.
    • The edintdimension:contractType dimension uses a custom code list defined in edintkos:EmploymentContractType.
  4. INE Vocabulary:
    • The vocabulary also reuses several properties from the INE vocabulary—such as ine:unemploymentRate, ine:employmentRate, ine:jobs, and ine:numberOfPeople—with the goal of extending the cube with additional employment-related indicators.
The employment cube model is shown in Figure 2, which presents its constituent dimensions and measures.
The structure of the employment cube is defined by the instance edintemp:DSD_EmploymentIndicators, which groups all the dimensions and measures of the model. In this case, the defined dimensions are: reference administrative region, sector, economic activity, reference period, sex, age, and contract type. As for measures, the model includes various counts and indicators related to employment, such as the number of active, employed, and unemployed individuals; registered contracts; job seekers; registered unemployment; Social Security affiliations; unemployment rate; employment rate; job positions; employment profiles; and the total number of people.

Example 1: Number of employed persons by area, period, sex, and age group back to table of contents

This example represents data corresponding to the number of employed persons in a given administrative region, for a specific reference period, broken down by sex and age group.

The steps required to represent a specific observation are described below. 1) Definition of the dataset and its relationship to the data structure: There is a dataset instance, represented by ex:dataset/DS_EmploymentIndicators, which is linked to the structure edintemp:DSD_EmploymentIndicators via the qb:structure property.
2) Identification of relevant dimensions and measures: Although the structure edintemp:DSD_EmploymentIndicators contains all the dimensions and measures of the employment cube, this example uses only the dimensions edintdimension:refAdminRegion, edintdimension:refPeriod, edintdimension:sex, and edintdimension:age, along with the measure edintmeasure:employedPopulationCount. It is important to note that the dimension edintdimension:refPeriod has time:Interval as its range; therefore, the reference period must be represented by an explicit instance of a time interval.
3) Defining an observation in the dataset: The final step consists of creating an instance of qb:Observation and linking it to the dataset using the qb:dataSet property. Subsequently, the corresponding values ​​for the selected dimensions and measure are assigned.
This observation indicates that, in the municipality of Zaragoza, during the time interval corresponding to the year 2025, the number of employed women in the 25–29 age group is 12,543. This example shows how a single observation within the cube combines various dimension values ​​with a specific measure to represent an employment indicator. Likewise, this same structure can be reused to represent other measures within the cube, such as the number of active individuals, unemployed individuals, registered contracts, job seekers, registered unemployment, Social Security affiliations, unemployment rate, employment rate, job positions, employment profiles, or the total number of people.
